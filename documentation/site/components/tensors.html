TensorDC

As you will see by browsing the code, plain torch.Tensor(s) are rarely used inside Matformer. Instead, all tensors are wrapped inside a custom dataclass, whose base is called TensorDC. The reason why TensorDC are used inside Matformer is twofold.

Padding and unpacking

A PaddedTensor is a datastructure where a tensor with batch dimension (B,S) is supplied with a boolean padding mask. The padding mask should have FALSE for each position that contains true data and TRUE for any padding position. Having defined a PaddedTensor gives several advantage. First of all, you will not have to worry again about the padding mask: this will be embedded into the tensors' dataclass. Then, you will have access to the .unpad() method. The .unpad() method of PaddedTensor objects convert the PaddedTensor into an UnpaddedTensor. An UnpaddedTensor stores only the real tokens, concatenated into one flat (total_tokens, ...) tensor, together with the indices that say where each token came from, the cu_seqlens boundaries of every sequence, max_seq_len, original_seq_len and batch_size. Varlen kernels use this layout, so the same batch can be passed to a padded kernel or to a packed kernel. Other useful methods available in the PaddedTensor objects are .detach(), which returns a list of tensors each of its "true" length, without any padding, and .pad_right() which converts the padding convention from right-padding to left-padding, so the real tokens are flush-right and the pads sit on the left. Autoregressive generation uses this layout, because the last position must be a real token.

Additional data

The TensorDC objects can carry with themselves additional data apart from the tensor itself and its padding mask. For example, a PaddedTensor needs a padding_mask, an UnpaddedTensor needs its cu_seqlens, and an attention implementation may need a document mask. The fields that every instance of a class needs are dataclass fields; everything else goes in one of the two dictionaries below. Sometimes those extra tensors should follow the main tensor during the padding/unpadding operations. In those cases, the tensors should be added as "following_attributes". A typical example is the "cloze_mask" used by masked models and used in the training step to recall if at that position there was a normal token or a [MASK]. The cloze_mask should be of the same shape of the original tensor, thus it will be included in the "following_attributes". On the contrary, an example for an attribute that should NOT follow the main tensor in its pad/unpad tour is the "same_doc_mask" tensor. This tensor is generated by the default Matformer dataloaders to signal if the current chunk belongs to the same document of the previous batch (more info same_doc_mask below). In this case, it will enter inside the attributes. While the following_attributes must be torch.Tensor of a compatible shape with the main tensor, the attributes are completely free. They can be tensors, such as the "same_doc_mask", but even other types. For example, a convention in Matformer is to keep the ["metadata"] key of the attributes dict free to store metadata of the documents contained in the batch. While it may seem weird to carry metadata (such as author, genre, year and so on) inside the TensorDC, it proved to be an handy solution for experimental scenario such as when a plugin connected deep inside the model (ex. for interpretability purpose) should access the metadata to store them in an external database together with the models' intermediate activations.

To run a plain-tensor nn.Module over a TensorDC, keeping the wrapper and all its attributes, use the sugar x.apply(module).

The same-document mask

A batch is not always a set of independent rows. In a packed stream, a row can continue the document of the previous chunk, and a recurrent mixer must know whether to carry its state across the boundary. The dataloader puts this information in the batch attributes:

  • is_same_document in a raw dataset item becomes same_document_mask, a boolean tensor of shape [B] (True means "this row continues the previous one");
  • the value is None when the dataset has no notion of documents, and the tensor is then absent.

Older code calls the same concept same_doc_mask; the two names refer to the same flag. Because its shape is the batch dimension and not the sequence dimension, it belongs in attributes, not in following_attributes: padding and unpadding must not touch it.

Classes

Class What it adds Typical use
TensorDC the base wrapper: tensor, tensor_order, following_attributes, attributes the type every model receives
NormalTensor no padding, no packing; pad() is a no-op generation, single examples, pooled outputs
PaddedTensor a boolean padding_mask (True = padding) the default training path
UnpaddedTensor indices, cu_seqlens, max_seq_len, original_seq_len, batch_size packed / varlen kernels

PaddedTensor.unpad() and UnpaddedTensor.pad() are inverses. detach() returns one tensor per batch element with padding removed; from_rows() rebuilds a padded tensor from variable-length rows; reverse() flips each packed segment in place. The layout helpers (layout, segment_ids, reverse_index) are cached per cu_seqlens, so a batch pays for them once per step even when every layer uses them.

Tensor operations

+ and * operate on the wrapped tensor and leave the attributes untouched, which is what residual connections and gated MLPs need. to(device, dtype) moves the tensor and every tensor-valued attribute. has(key) checks both dictionaries. apply(module) runs a plain module on the tensor and returns a new wrapper, which is the idiom for a kernel that knows nothing about Matformer.

stats() returns the full description of the wrapped tensor, using the one implementation in matformer.utils.tensor_stats. Padding is excluded by default; pass include_padding=True to count it. The same dictionary is what ParameterEditor.stats() and the analysis tasks produce.

apply_kernel(module, x) is the tolerant version used inside kernels: it applies x.apply(module) when x is a TensorDC and calls the module directly when it is a plain tensor. That is what lets the same linear layer work inside an MLP (plain tensor) and at the top level (wrapper).
