# HuggingFace

Matformer can load a HuggingFace model, convert its configuration, train or evaluate it, and publish it back as a HuggingFace repository. The two directions share the adapter definitions and the stable parameter names, so a model does not have to be re-imported from scratch.

## Loading a checkpoint

```python
from matformer.matformer_wrapper import load_model

result = load_model(
    path="hf://sapienzanlp/Minerva-350M-base-v1.0",
    map_location="cuda",
    dtype="bfloat16",
    inference=True,
)
model, configs = result["model"], result["configs"]
```

`load_model` calls `make_holder`, which sees the `hf://` scheme and builds a `HuggingFaceCheckpointHolder`. A local folder works without the scheme. The holder reads `config.json`, picks the adapter from `model_type`, discovers the weight files and streams the stable weights into the wrapper.

If the adapter does not exist for that `model_type`, the holder raises a `NotImplementedError` listing the supported families. Adding one is a YAML file in `matformer/loading/adapters/huggingface/<model_type>.yaml`; see [[loading/checkpoint-holder#the-adapter-definition | the adapter definition]].

## Converting the config

`HuggingFaceCheckpointHolder.get_configs()` calls `MatformerConfigs.convert_and_import(definition, source_config)`. The adapter's `*_mapping` sections say which HF config field feeds which Matformer field, and `derived` sections compute values (for example a head count from another field). The result is a normal `MatformerConfigs`, so the model is built by the same code as a native one.

The tokenizer section is filled with the checkpoint folder, so the tokenizer is the one the model was trained with. An override for any section uses the same `configs` argument as for a native checkpoint:

```python
result = load_model(path="hf://org/model", configs=my_configs)
```

## The HuggingFace shell

`matformer/loading/huggingface_integration.py` provides a `PreTrainedModel` shell for code that expects the `transformers` API. `from_pretrained` delegates to `load_model`, and every forward delegates to the Matformer wrapper.

```python
from matformer.loading.huggingface_integration import (
    MatformerModel, MatformerForCausalLM, MatformerForMaskedLM,
    MatformerForSequenceClassification, MatformerForTokenClassification,
)

model = MatformerForSequenceClassification.from_pretrained(
    "org/my-matformer-checkpoint",
    num_labels=7,
    pooling_type="mean",
)
```

Supported task classes:

| Class | `matformer_task` |
|-------|------------------|
| `MatformerModel` | base model |
| `MatformerForCausalLM` | causal language model, with `generate` |
| `MatformerForMaskedLM` | masked language model |
| `MatformerForSequenceClassification` | sentence-level classification |
| `MatformerForTokenClassification` | token-level classification |

`from_pretrained` accepts the extra kwargs `checkpoint`, `matformer_config`, `num_labels`, `pooling_type`, `device`, `dtype`, `token`, `revision` and `cache_dir`. HF-only kwargs that do not apply are accepted and ignored. `device_map` is not supported: Matformer does not shard a model across devices, so use `device` or move the model afterwards.

Classification over a non-classification checkpoint is handled by `_apply_task`: the model section switches to Matformer's `classification` variant, and the existing `ClassificationPlugin` provides the head.

## Publishing

`MatformerPreTrainedModel.save_pretrained(directory)` writes a self-contained HF repo:

* `model.safetensors`: the stable state dict, deduplicated and on CPU;
* `matformer.yaml`: the Matformer configs;
* `config.json`: the HF config, with `auto_map` pointing at the installed package;
* `modeling_matformer.py`: a small shim generated by `create_modeling_file()`;
* the tokenizer, when `save_tokenizer` is true.

The folder is loadable by both frameworks: Matformer reads it with `MatformerCheckpointHolder`, HuggingFace reads it through `auto_map`. `huggingface_publish.py` contains the higher-level publishing helpers.

## A minimal fine-tune

```yaml
model:
  type: classification
  base_model: "hf://sapienzanlp/Minerva-350M-base-v1.0"
  base_model_hf: true
  num_classes: 2
  pooling_type: cls

training:
  data: train
  optimizer: adamw
  lr: 2e-5
  max_epochs: 3
```

`base_model` makes the trainer build a `HuggingFaceCheckpointHolder` and inherit the model and tokenizer sections from it. The classification head is added on top, and the freeze configuration decides whether the backbone is trained or only the head. The tutorial version is in [[tutorials/use-matformer-model | Use a Matformer model from HuggingFace]].
